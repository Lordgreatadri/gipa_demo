# Prototype Acceptance Criteria

·       
Client can navigate a professional public portal
in light mode and switch to dark mode.

·       
Admin can authenticate and access only permitted
modules.

·       
Admin can create/edit a district and demonstrate
draft/review/publish.

·       
Authorized user can create an investment
opportunity with mandatory validation.

·       
Opportunity can move through the defined
approval lifecycle with recorded actions.

·       
Public user can filter opportunities by region,
district, sector, type and status.

·       
Map displays opportunity locations and district
boundaries using approved geospatial data.

·       
Investor can submit an inquiry against an
opportunity.

·       
Workflow/inquiry events generate configurable
notification jobs.

·       
Audit log records material administrative/API
activity.

·       
Dashboard demonstrates at least the core
reporting indicators named in the TOR.

·       
API is versioned and exposed through OpenAPI
documentation.

·       
Maintenance mode demonstrates public offline
messaging while approved administrators remain accessible.

·       
Prototype demonstrates responsive behavior
across desktop, tablet and mobile.

# 8. Prototype Modules

**A. Public Portal: **Landing
page; search; district list/detail; opportunity list/detail; interactive map;
compare; investor inquiry; responsive/PWA shell.

**B. Authentication
& Access: **Login, password reset, session controls, MFA-ready
architecture, roles, groups, permissions and district-level restrictions.

**C. Region &
District Management: **261-district registry; region hierarchy; geometry;
readiness score; economic data; population; area; import GeoJSON;
draft/review/publish workflow.

**D. Opportunity
Management: **Structured opportunity form; location; sector/sub-sector;
enterprise type; status; rationale; financials; contacts; documents; lifecycle
workflow.

**E. Workflow &
SLA: **Draft → pending approval → approved → active → completed/cancelled;
submit/approve/reject/reassign; SLA timers and breach alerts.

**F. Geospatial &
Investment Map: **PostGIS; GeoJSON; nearby/bounding-box/polygon queries;
cascading filters; map markers and district boundaries.

**G. Investor
Inquiries: **Public inquiry form linked to opportunity; tracking; assignment;
response status; email notifications.

**H. Dashboard &
Reports: **Regional distribution; sector investment; opportunity timeline;
readiness distribution; job creation; infrastructure quality.

**I. Audit &
Compliance: **Material admin/API action logging; actor, timestamp, IP, route,
action, entity and before/after data where appropriate; retention/export.

**J. Notifications: **Configurable
email templates for submission, approval, rejection, inquiry and SLA breach.

**K. Settings &
Maintenance: **Workflow, notification, audit, onboarding and maintenance
settings; admin/IP whitelist; graceful public maintenance page.

**L. API: **Versioned
REST resources; JWT requirement for API as stated in TOR; OpenAPI
documentation; compatibility policy.

**M. Onboarding &
Messaging: **Admin onboarding tour, preferences and controlled user-to-user
administrative messaging.

**N. PWA: **Service
worker, installability, offline fallback and health checks.

 N T E R A C T I V E D E M O ( F R O N T - E N D O N L Y ):
 A high-fidelity, clickable demonstration of the full system, covering investor onboarding, matchmaking, certificate issuance with QR
verification, an AI assistant with simulated responses and internal dashboards, built with mock data and no backend. GIPA sees exactly how
the platform will look and behave, but it cannot be used as a live system: no real data, no integrations, no production hosting. If the project proceeds to the MVP, which is itself in dev, the demo’s design assets and front-end components carry directly into the MVP.
